# 小程序退役与项目目录精简设计

## 目标

在不影响巡防百科静态网站、历史资料和交付物的前提下，删除当前不再需要的微信小程序实现链路，清理对应的失效测试、配置和当前规划文案，使仓库继续以网站建设与维护为核心。

## 删除范围

### 小程序实现

- 删除整个 `miniprogram/` 目录及其中 66 个已跟踪文件。
- 删除根目录 `parse_html.py`。该脚本只负责从网站 HTML 生成小程序数据，退役小程序后不再有保留价值。

### 小程序专项测试

调整 `tests/test_sensitive_content_removal.py`：

- 删除 `parse_html.py` 仓库路径测试；
- 删除警情小程序整改状态测试；
- 删除警情小程序空数据测试；
- 删除勤务小程序整改外壳测试；
- 删除小程序首页敏感案例测试；
- 新增退役契约测试，要求 `miniprogram/` 与 `parse_html.py` 持续不存在。

网站敏感内容、删除页面、搜索索引和内部链接相关测试继续保留。

### 失效配置与当前规划文案

- 从 `tools/check_site_links.py` 的网站扫描排除目录中移除 `miniprogram`。
- 将 `tools/generate_demo_ppt.js` 中当前使用的“微信小程序迁移”规划改为“移动端体验优化”，以后重新生成汇报材料时不再宣示小程序迁移计划。

## 保留范围

- 完整保留 `deliverables/`，包括当前已有的未提交、删除和新增文件状态；
- 完整保留 `docs/` 中的历史设计、实施计划、审计报告和项目演进记录；
- 保留 `.codex-doc-review/`、通用 `tools/`、网站测试、内容清单和搜索构建工具；
- 保留网站运行所需的 HTML、CSS、JavaScript、图片、视频、法律数据及认证逻辑；
- 保留 `.nojekyll`、`CNAME` 和 GitHub Pages 发布方式；
- 不修改现有网站 URL、模块路径和页面内容。

历史文档与既有交付物中对小程序的记录属于项目历史，不进行追溯修改。

## 恢复策略

小程序文件通过正常 Git 删除提交退役，不重写 Git 历史。未来如需恢复，可从删除前的提交中恢复 `miniprogram/` 和 `parse_html.py`，再依据当时的设计与计划重新评估兼容性。

## 验证

实施完成后必须验证：

1. `miniprogram/` 和 `parse_html.py` 不存在；
2. 活跃代码和测试中不再引用小程序实现链路；
3. 除本次新增的设计与实施计划文档外，历史 `docs/` 未被修改，`deliverables/` 未被本次提交修改；
4. 站点结构、敏感内容、搜索索引和内部链接测试通过；
5. 完整自动化测试通过；
6. GitHub Pages 部署成功；
7. 线上首页和主要模块页面仍可正常访问；
8. `deliverables/` 原有未提交状态在实施前后保持一致。
